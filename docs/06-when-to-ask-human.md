# When to Ask a Human

AI is a great coding assistant, but it has limits. Knowing when to stop and get help from a person is a skill — and it's what keeps you and your projects safe.

## Ask a human when...

**1. The AI is going in circles**
You've asked for a fix three times, and each answer introduces a new problem or repeats the last one. Time to ask a person — a friend, teacher, mentor, or an online community.

**2. Security or money is involved**
Code that handles passwords, payments, banking, or personal data needs a human review before it goes near real information. AI can make subtle security mistakes that are hard to spot.

**3. You're copying code you don't understand**
If you can't explain what a piece of code does, don't run it — especially not on your main computer or with real data. Ask someone to walk through it with you.

**4. It's for work, clients, or production**
AI-written code for a paying project or a public website should be checked by another person. Your reputation is on the line.

**5. It's health-related**
AI can give general information, but never medical advice. If you're building anything related to health, have a qualified professional review it. Asdale Dynamics builds healthcare-worker AI aids for education only.

**6. You feel stuck or frustrated**
Learning is supposed to stretch you, not hurt you. If you've been stuck for more than an hour, step away and ask someone. A five-minute conversation can save an afternoon.

## Where to find humans

- Friends, family, or coworkers who know a little tech
- Local coding meetups or library workshops
- Online communities (forums, Discord servers, Reddit) — just don't share secrets or personal data
- Your local school or community college
- Asdale Dynamics: we make beginner-friendly tools and welcome questions

## What to bring when you ask

To get the best help, bring:

- What you're trying to do
- What you've tried so far
- The exact error message (copy and paste)
- The code you're working on (without secrets in it)

Good helpers will teach you, not just fix it for you.

## Remember

Asking for help isn't failure. Every experienced programmer asks for help all the time. The goal is to learn and build things — not to do it all alone.
